## 6. Silver Architecture

`SILVER` is the trusted/conformed zone and contains exactly CUSTOMER, ACCOUNT, PAYMENT, PAYMENT_EXCEPTION, SLA_EVENT, OPERATIONS_TEAM, OPERATIONS_USER, REFERENCE_EXCEPTION_REASON, REFERENCE_PAYMENT_THRESHOLD and GOVERNANCE_REFERENCE. `SILVER_QUARANTINE` is a separate physical schema within the logical Silver trust boundary, consistent with Landing → Bronze → Silver → Quarantine/Gold.

## 7. DQ Rule Model

`GOVERNANCE.DQ_RULE_CATALOG` separates technical `SLV-*` identifiers from `GOV-SLV-*`, control families and scenario IDs. Blocking rules yield `QUARANTINE`; admitted records expose `PASS`. Rules cover schema/type parsing, completeness, domains, relationships, reference effectivity, temporal order and deterministic duplicate disposition.

## 8. Quarantine Model

`SILVER_QUARANTINE.REJECTED_RECORD` stores a deterministic quarantine ID, run/trace, entity and record identity, minimized Bronze reference, file coordinates, ingestion run, rule/scenario/severity/outcome/reason, time and synthetic flag. It references immutable Bronze instead of duplicating raw personal or financial payloads.
